## 评分与验收口径

分别报告模型原始输出、系统校验后的推荐和规则回退。系统回退正确不能记作模型正确；有响应不等于完成用户目标。每个模型场景记录三次输出及一致性，按条件分层展示适用分母，不用重复次数扩充独立样本数。

票务检查ID及事实是否来自冻结候选、席别和硬条件是否保持、报价未知是否保留、日程阶段和余量是否有证据；偏好层支持并列和偏序。PS04/PS09不评唯一排名，PS10空结果符合本次条件仍须说明范围且保持零调用。PS12用独立路线矩阵和日内约束核算交通、餐次、锁位、营业假设及最终时间，不能用生产规划器输出充当参考。

以下是实验执行验收条件，不代替人工参考确认或USER产品验收：

1. 30个计划槽位均有终态或明确未运行原因；失败、拒绝、回退和中断不丢弃。缺失证据记ERROR，未适用/未评保留各自状态。
2. 每槽保存输入/源码版本、原始模型建议、最终结果、前后状态、模型或规则路径、用量回执及本地脱敏Trace；不生成虚假LangSmith云链接。
3. 待审参考只进入诊断，正式检查和正式质量分数保持空；接受集合不因实际输出而修改，不将参考分歧、模型问题、工程取证问题与故障注入合成一个失败率。
4. 记录全部实际请求及输入/输出token；超预算、认证失败、无法判断是否计费、usage缺失或实验中断后，停止继续派发并保留预留，不自动重跑。
5. 依赖版本、业务库、`.env`、原数据集、原P3/P4报告及Git HEAD/索引核对不变。所有写入仅限仓库外新实验目录和每槽独立SQLite。

## 执行前准备与批准边界

当前`evals.conditional`仍只支持离线回放，v1真实执行器的模型和费率固定为Pro。**本计划没有把现有命令直接切到Flash，也没有开放真实执行入口。** 用户确认预算后，先在隔离执行层完成v2输入/评分绑定、Flash费率和调用前预算守卫适配，断网验证门禁，再发起本计划内请求；不修改产品运行配置、参考或依赖版本。
