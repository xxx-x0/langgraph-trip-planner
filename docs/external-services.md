# 外部服务调用与失败恢复

2026-10-24按已提交3b3a93c核对；本机单用户，适用于当前锁定依赖。下方带LTP日期的记录为历史范围。本次文档检查未升级依赖，也未重测真实服务。

## 调用入口

`app/services/external_calls.py` 负责期限、取消、有限重试、并发、短期缓存和脱敏观测。三个 MCP 服务通过 `mcp_gateway.py` 返回受控 LangChain 工具，保留服务器的名称与参数 schema；`get_tool()`、`get_tools()`、服务方法和节点 helper 都进入同一调用策略，无法通过获取工具句柄绕过重连。节点继续负责把地点、餐饮、酒店等服务数据转成领域模型。

共享解码处理字符串 JSON、MCP文本块、`structuredContent`及ToolMessage错误，保留服务返回的坐标、价格、来源等字段。`isError`、业务失败或坏响应不得作为空成功结果缓存。工具执行错误与协议错误的区分依据 [MCP工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)；实际传输仍使用锁定适配器，AMap/Bing为SSE，AIGoHotel为Streamable HTTP，没有在本次迁移协议。

| 服务 | 运行调用点 | 当前入口 |
| --- | --- | --- |
| AMap | 发现与缓存、地理编码、聚类、天气、餐饮、路线、地图/POI API | 服务方法或受控工具 → MCPGateway → invoke_external |
| AIGoHotel | 逐日酒店候选与详情 | 同上；沿用实际工具参数 schema |
| Bing | 攻略搜索，搜索结果网页抓取 | 同上；抓取参数为搜索结果UUID及urlMap，旧单一url参数已修正 |
| LLM | 编排、AI选景/重排、时长及兼容完整规划图的生成等 | invoke_llm；结构化模式经invoke_structured_or_json |
| Open-Meteo | 高德无法覆盖日期时的天气补充 | 城市编码及天气请求共同受invoke_external约束 |
| Unsplash | 可选封面图片 | 异步HTTP调用，经invoke_external；缺图返回明确降级，不阻塞行程编辑 |

运行代码中的外部 `.ainvoke()` 已收敛到公共边界；LangGraph本身的 `.ainvoke()` 是图执行。兼容测试工具的helper也使用共享策略。旧HelloAgents参考文件不属于运行路径，不在本次清理。

## 期限与重试

| 调用 | 总期限 / 单次尝试上限（秒） | 最多尝试 | 同服务并发上限 |
| --- | --- | --- | --- |
| MCP工具列表 | 20 / 15 | 2 | 1 |
| MCP普通调用 | 30 / 20 | 2 | 1 |
| 酒店搜索 | 45 / 20 | 2 | 1 |
| LLM | 默认60 / 30 | 2 | 2 |
| Open-Meteo | 20 / 12 | 2 | 1 |
| Unsplash | 10 / 8 | 1 | 2 |

节点可以指定更短期限；例如地点详情增强为10秒且只尝试一次。兼容helper的参数仍叫 `max_retries`，含义为最多尝试次数，最多2次，并非额外重试次数。总期限覆盖排队、冷初始化、工具调用、重连及退避；父操作期限取更短者。整日路线的所有路段与候选交通方式另有60秒总期限。图片API的两种查询共用12秒期限。

只对超时、连接故障、限流和暂时不可用做有限重试；认证、无效请求、坏响应和未分类工具错误不盲目重试。连接故障或超时后重新加载原始工具句柄。取消继续向上传播，释放并发位置。移除了图层搜索节点的额外RetryPolicy，ChatOpenAI的SDK重试设为0；日程格式校验可以重新生成，但外部服务故障不会在该业务循环中再次叠加重试。

上述期限依赖底层异步库正常响应取消；不是外部服务可用性保证。实例在进程内复用，适配器在调用期间管理MCP会话；应用关闭时重置三类MCP客户端、关闭LLM客户端并清空缓存和并发状态。

## 缓存、能力配置与观测

仅稳定地点详情、地理编码和逆编码短期缓存300秒，最多256项，返回副本；不缓存失败、天气、酒店报价、搜索、路线、模型输出或保存操作。请求参数只参与哈希缓存键，不进入观测日志。餐厅详情增强的熔断仅暂停当前批次，后续批次能够恢复，不再保留永久熔断状态。

`LLM_STRUCTURED_OUTPUT_MODE` 支持 `json_prompt`（默认）、`auto` 和 `function_calling`。后两种会按实际请求探测结构化能力；不支持时在同一总期限内回退JSON解析，不再用模型名称黑名单猜测。认证失败、超时和连接故障不会被当作能力不支持。探测结果随当前LLM实例保留，重置或重启清除。`EXTERNAL_LLM_TIMEOUT` 控制LLM总期限，默认60秒；原 `LLM_THINKING_MODE` 配置继续保留。

观测记录服务、操作、结果类别、尝试次数和耗时，进程内保留最近1000条。公共错误只含安全的服务/步骤描述、失败类别和可重试信息；不包含原始请求、响应或异常文本。日志格式化同时脱敏配置中的密钥、认证头及URL凭据，包含异常堆栈。验证用完整业务回执另存本机证据目录并检查凭据，不写入仓库。

## 用户恢复路径

五条前端SSE请求共用 `services/sse.ts`，期限保持到响应体结束；完成前EOF、坏事件或网络中断会明确提示失败步骤，完整终止事件后关闭流。服务器不再在完成后无限发送心跳。

发现页保留当前选择、日期分配和天气的会话快照，刷新可恢复同一表单的选择。草稿创建以持久化于浏览器会话的请求ID识别同次重试；服务器检查输入指纹，串行处理同键请求并在SQLite写事务中再次检查，避免响应丢失后重复创建。元数据放在现有JSON中，不增加表结构。完成已被客户端确认后清除待重试ID；明确改变输入产生新的请求。删除或过期清理后的草稿不属于该恢复保证。

地图失败时普通草稿装配/重算不保存估算路线，保留上次成功状态并允许重试。旧一次性规划路径的估算路线带 `is_estimated` 和明确说明。LTP-10起草稿每日说明和定稿标题/全局说明直接投影结构化事实，不依赖叙述模型调用；AI重排仍使用LLM，失败不写部分修改。定稿装配或事务失败不写部分历史。定稿响应丢失后可重试取得原历史；重新打开已定稿草稿会跳转对应历史，避免显示可编辑控件。保存事务、锁定、删除和恢复规则继续沿用LTP-3/LTP-6；LTP-10逐日写入还比较原快照，迟到结果返回409，前端重新读取最新保存内容。

回归、真实服务结果、失败和限制见 [LTP-2/LTP-7交接](ltp2-ltp7-handoff.md)。真实服务暂不可用不等于模拟测试失败，也不能把模拟通过当作服务实际成功。

LTP-10复用此前真实素材进行本轮真实地图/AI编辑、说明刷新与定稿验证；刷新行程说明不发外部请求，证据与范围见 [交接](ltp10-handoff.md)。这不代替LTP-2/7的历史真实全链路或各服务可用性验证。

LTP-11的AI重排共享110秒operation_deadline，覆盖模型、初次实际路线、最多一次保留旧安排的路线核对和保存；子操作取父剩余期限，不追加模型调用或无限恢复循环，前端原120秒不变。模型/地图错误继续进入公共安全错误边界，超时取消后不写部分日程。有效AI插入位置保留，实际餐次/可解析营业时段不符合时不能靠标签通过，见 [LTP-11交接](ltp11-handoff.md)。


### LTP-15/16 餐饮推荐补充（2026-10-15）

仍使用高德 MCP，没有切换供应商。午晚餐检索按活动锚点；专程模式可加城市检索，每餐预算缺少已知合适候选时补查简餐。检索返回可能不含任何坐标/价格，详情额度在原菜系与简餐之间交错分配，正餐最多8家、其余每类最多3家；串行及公共边界仍有效。`POST /api/trip/draft/{id}/day/{day}/dining-options` 采用80秒总期限，前端85秒；查询完成前不更改已安排餐厅，空结果保留旧池，部分分类空结果保留旧分类及旧时间，迟到结果比较每日和候选原JSON后409。查询时间为本次快照读取时间，公共短期缓存可能命中，不代表商户更新时间。没有导航查询的候选绕路值明确标为直线步行折算；换店后才沿用真实路线计算。证据及局限见 [LTP-15/16交接](ltp15-ltp16-handoff.md)。
