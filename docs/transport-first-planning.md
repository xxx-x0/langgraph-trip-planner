# 交通预留与单城重排

2026-10-27。针对先排满景点、后选长途班次造成抵离日冲突的问题，增加规划前的时间预留和草稿中的明确重排。沿用已有查票、候选比较及确认保存，不新增票务数据源。

## 使用与兼容

新建单城旅行填写出发城市后，未定班次的去返方向默认分别预留首日、末日。可以改为填写目的地开始／结束活动的预计时间，或主动选择暂不预留。表单日期和天数表示整趟出行，含在途；目的地摘要另列完整可用日、部分可用日和暂无游玩时间的日期。预计边界已包含用户本次暂定的接驳预留，实际班次填写后按班次及原缓冲计算，不叠加两套边界。

旧记录没有 `journey.planning` 时保留原规则，读取不写入新默认值。多城市已有相邻交通与两侧当天调整继续沿用原路径，本次跨日重排入口仅用于单城草稿。未填实际班次的预留不表示已查票、已订票或准确住宿夜晚，住宿仍按既有实际抵离日期规则核对。

发现阶段按交通预留后的容量分配景点，交通日允许空白。用户明确按天指定且超出容量时提示修改，不擅自改成其他日期。自动分配放不下的选择保留为草稿待安排景点，不从本次选择中丢弃。骨架容量采用08:00—22:00与抵离边界的交集、游览时长和有限交通余量；它不表示市内路线、营业或餐次已经核实。每日编辑仍支持用户原有的早晚时间。

草稿页可手动修改交通后点“按交通重新安排并预览”，也可从与已存安排冲突的候选进入该预览。重排在副本进行：

- 受交通挤占的未锁定景点移出原日，保留游览时长，尝试放到其他日期；尚未装配的骨架也做同样的目录保护。
- 锁定景点、固定预约与手动用餐受保护，无法容纳时拒绝本次调整。已有删除清单不自动恢复。
- 自动用餐及休息无法容纳时明确列出取消项；跨日放入已有安排时保留该日已有正餐、锁定与固定时间检查。不会自动生成在途餐厅或新餐厅。
- 放入已有每日安排时重新核对必要路线、时间轴、已知营业与用餐规则。无路线或估算路线不能冒充验证成功。移到未装配日期时明确标注仍待路线和餐饮核对。
- 每次预览最多12批路线、总期限110秒，按有限次移除和逐日尝试寻找可行安排，不保证跨日最优或一定找到所有可行排法。

预览列出活动移动、时刻变化、用餐／休息取消、待安排清单和预算。用户勾选核对后才可确认保存；取消预览不会修改草稿。仍放不下的景点可选一天单独预览加入，或明确选择“不再安排”后预览确认。待安排未处理完时，页面和服务端均拒绝定稿。明确放弃的事实存入独立记录，不会在重算或装配中重新加入。

## 保存与字段

`Journey.planning` 包含 `arrival_policy`、`departure_policy`（`travel_day`／`time_window`／`unreserved`）及预计 `ready_at`、`leave_by`。没有实际班次的预计时间需在本趟日期内，按目的地时区解析。实际方向的班次和缓冲优先。

待安排及明确放弃的景点分别存入已有草稿请求JSON的 `_transport_unassigned`、`_transport_discarded`；API输出 `unassigned_attractions`。目录保存来源事实、原日期、原游览时长及待安排原因。新增字段均为JSON，没有ORM迁移，也没有改写旧业务数据。

`POST /api/trip/draft/{id}/journey-adjustment` 首次返回预览；确认时提交相同输入、`adjustment_id`、`preview_token` 和 `acknowledge_adjustments=true`。单独处理清单使用最多一项 `placements`，或明确 `discard_ids`。服务端保管最多32份预览，15分钟有效；重启、过期、输入或草稿改变时409，需重新预览。

预览完成后及确认事务内检查请求、每日详情、骨架、景点目录、酒店、餐饮、天气和状态快照。确认将交通、休息、跨日详情、景点目录和骨架同事务保存。失败、取消、迟到结果及竞争写入保留上次成功状态，已定稿记录不可编辑。费用和说明随保存的安排投影；待安排或未装配费用不当作已完整计入。
