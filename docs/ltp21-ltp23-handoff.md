## 用户能做什么

先填写整趟日期、出发和返家城市、同行人数、预算、节奏和必须去的城市，再比较当前顺序、停留晚数调整、反向或少去一城的备选。比较显示已知费用、晚数、换城负担及已知交通下的时间；未填票价不能被当成更便宜，未填班次不能被当成更快。

逐段查询、导入或手填交通，同段可比较六个备选；选择后先看受影响城市的活动时段、已知预算差额和已订安排，再确认保存。住宿可分区间填写每房每晚或整段总价，按全部房间和实际晚数汇总；未知税费、外币和未核价仍列待办。夜晚归属城市或在途；重复覆盖、日期不符和含缓冲的衔接冲突会提示。

每城进入原有发现和每日编辑流程，明确点击“将当前安排同步到整趟旅行”才更新整趟快照、预算与说明。允许休息或在途日不选景点，不自动删掉用户已有活动；未安排正餐仍待补充。交通变化复用已保存路线，保留锁定、删除、排序和餐次，无法容纳时保留原安排并报告冲突。日期、城市或人数不匹配的旧快照保留，但不继续计其过期费用。保存的整趟版本只读，可复制为新版本继续编辑。

## 实现与兼容

- `models/multicity.py`：旅行、城市引用、停留、住宿区间和相邻交通边。城市有独立标识，可记录 adcode/坐标；当前手动输入名称不伪造地理编码。
- `services/multicity.py`：统一投影、夜晚归属、费用和时间检查、城市方案、版本保存；`api/routes/multicity.py` 提供 `/api/multi-trips` 系列 API。
- 聚合存于现有 TripDraft.request_json，kind=`multi_city_v1`、ID 前缀 `mc_`、status=`multi_city/multi_saved`；单城市读取、删除和旧 TTL 清理不会把它当旧草稿。
- 城市工作副本显式导入请求、每日安排和候选上下文；原工作副本以后改变或过期，不会改变已保存旅行。新版本编辑从导入快照复制，不依赖原草稿仍存在。
- 预览 token 绑定整份旅行快照及新输入；所有聚合写入在一个 SQLite BEGIN IMMEDIATE 事务检查 revision。迟到写入返回409，投影异常回滚。前端输入改变即使比较/预览失效，换页面后旧响应不覆盖新旅行。
- CONTEXT 维护领域术语，取舍见 [ADR](adr/0001-whole-trip-snapshots.md)。未改 ORM 表结构、业务库、依赖锁、原75包环境，也未创建 Git 提交。

## 限制和后续验收

1. 这版是城市顺序/晚数规划与已填写交通的联动，不是全球路线优化器；接驳、候车、行李和办理缓冲为可编辑估计。自动建议不声称最便宜、最快或最舒适。
2. 休息以建议和允许留白实现，不自动强制删掉半天已有活动；空白日可继续手工补餐厅。复杂营业日、预约和连续多日体力仍须人工核对。
3. 手动住宿区间优先计费；改变实际酒店位置须回每日编辑重新核对路线，名字不同即提示，不能把旧酒店路线当成新酒店的路线。
4. 同步失败保持整趟原版本；城市工作副本仍保留。另一窗口改变整趟日期/交通后，需回整趟页面重新进入，不自动覆盖并发修改。
5. 两条不同完整多城市路线、含真实已订票和完整实时价格的外部验收仍不能由本轮人工票价样例代替。Nexo P12 相应标准保留未完整验证，不代替用户接受。
