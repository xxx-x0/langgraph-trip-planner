## 固定/可移时刻与低负担交互规格

另为PR01准备直接可用、仅延后非固定活动、需要提前出发侧安排、固定预约冲突、需要取消内容、过期快照六种交互条件。它们是工程验收条件，不增加新的模型调用计划：

- 直接可用沿现有采用/预览/确认；仅移动可移时刻在同一预览突出差异，普通路径不增加开关或独立确认。
- 已存开始时刻固定性不明，不能由模型自行判断预约可移。由数据契约记录计划时刻、最早下界、固定区间及依据；旧数据缺字段时保留原时刻核查，调整候选明确带条件。
- 取消景点/餐次/休息走用户主动调整入口，保留已有核对取消项；不混进“直接可用”。锁定保护、删除状态、失败保留与CAS规则不放松。
- 未说明偏好先展示真实取舍；缺硬条件或明确要求冲突才追问。没有差异就如实说明，不为凑卡片/解释生成不存在优势。
- “更多要求”按需展开，席别/价格上限不设为新必填；偏好改变沿现有重新筛选入口。操作次数按整个任务统计，不能把藏在多层折叠中的额外步骤当零负担。

3. 原先只接受balanced/price/time/daytime的接口不能承载未说明偏好、硬席别和参数化时段的完整语义。需先定契约/页面/评分的最小变更，不能只改提示词冒称已实现。
4. 新评分应支持分阶段可行性、条件化接受集合和偏序，按偏好分层报告适用分母/覆盖率；用已声明正反例验证，未知/缺证据不变成PASS。
