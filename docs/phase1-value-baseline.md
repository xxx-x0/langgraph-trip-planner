## 实施前固定的测量规则

- 自动回归检查事实约束；真实API任务测响应耗时、失败和保存一致性；实际页面走查测操作障碍；真人评价测采纳、理解及信任。四类证据分列。
- 总操作时间为人开始任务至完成判断；等待时间独立计。脚本墙钟/API响应总和仅为代理技术基线，不能改名为用户耗时。
- 修改目标数与实际操作次数分别统计。外跳核对次数只统计实际发生的核对；未做外跳不能推断不需要外跳。
- 建议采纳率=用户明确采用的可决策建议/向该用户展示并获得评价的建议。无人评价时为null，不能用脚本选中率代替。
- 预算可信度：可判定的金额都有来源、时效、币种和适用条件；缺项保持未知；不得把未知填0或把整段价当每晚价。此类错误目标为0。
- 说明理解：用户能指出当天重点、下一步、未确定事项，各1分；目标为至少80%的受测任务得3分。属于待验证目标，未招募不打分。
- 推荐理由：适合本次需求、解释代价、有可核对依据，各1分；目标为至少80%的受测推荐得3分，不能用泛化赞美凑分。
- 抵离冲突：已知交通约束下冲突目标为0；当前未支持的任务不得计为通过。
- 在同任务条件下，以减少人工修改和外跳核对为改善方向；用户总耗时目标较基线减少20%，同时不得降低采用率。样本小且重复任务有熟悉效应，仅作探索性判断。

指标先于代码修改冻结；最终未达到或无法测量时保持失败/未验证，不倒推及格线。阈值为本轮研究预设，由用户验收，并非已经获得用户效果证明。
