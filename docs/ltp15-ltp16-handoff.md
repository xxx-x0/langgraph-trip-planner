## 现在能做什么

- 酒店优先比较与本次游玩区域的直线距离，再参考星级；保留完整分店名。页面解释位置、住宿晚数和报价入住条件，远距离及未知条件明确提醒。供应方营销介绍折叠并标明未经独立验证。沿用 P02 房型报价及预算口径，不恢复星级估价。
- 首页可填写每人每餐预算、饮食要求，选择顺路用餐或愿意专程去。正餐搜索围绕预计午晚餐活动位置；草稿中依据保存时间轴的前后活动（包括其他用餐）重新计算匹配。专程模式增加城市检索，预算内没有已知候选时补查简餐。
- 每个时段最多展示三家备选，比较参考人均、来源、查询时间、营业窗口与位置。绕路分钟明确是直线距离按 4 公里/小时折算，**不是导航时长**。没有菜系、菜单、份量、排队、评价量或儿童设施事实时保留未知；泛化的“餐饮相关”不当作菜系。
- 可以直接换餐厅，也可以“按当前安排重新找餐厅”。换店后调用真实地图路线并检查营业窗口；新店停止营业或不能容纳用餐时间时拒绝保存。重新查找只更新备选，不修改已安排餐厅；空结果、超时或期间安排变化保留旧状态。
- AI 保留手动选定的餐厅和位置，以及原有正餐数量、餐次、删除与景点锁定规则；候选价格、位置和营业事实取自服务端，浏览器与模型只决定选择和位置。
- 每日说明讲当天重点、当前要求对应的节奏、游览与交通时间、时间不足时的取舍，不再逐项复述时间轴。慢游、带长辈、带孩子、美食优先的差异来自本次输入。待确认事项集中展示，完整时刻在独立时间安排中；草稿和结果都可查看。总体建议也改为段落表达。
- 手机日期和操作按钮分行；白色餐厅卡片不再受暗色主题影响而出现白字，控制项支持键盘访问。

仍然用确定性事实生成说明，没有增加模型写文案请求；没有读取隐式历史偏好。新字段只写 JSON，ORM 和 SQLite 表结构未改，依赖锁未改，无 Git 提交。

## 明确没有证明的事

1. 无真人阅读测试、采纳/拒绝访谈和实际就餐体验。P04 c5、P05 c5 的真人部分为 NOT_VERIFIED，产品价值仍为 UNVERIFIED。
2. 直线绕路估算不含路网、等待、拥堵和实际步速；选择后才计算实际行程路线。酒店排序仍按位置代理指标，未做多酒店交通总成本比较，也没有新增跨日换酒店编辑。
3. 高德当前常只返回泛化分类，不能凭店名推断招牌菜、无过敏原或适合儿童。每餐预算不是饮食限制认证，也不是实际支付价。日期相关营业例外不当作已核实开放。
4. 时间戳代表本次读取快照（可能经过公共短期缓存），不是商户更新时间；超过一天会提醒复核。供应方没有关闭信息时无法保证店铺仍营业。
5. 酒店儿童/多房条件回显、税费与最终落地价的 P02/P03 限制继续有效；未签约、未付费接入新供应商。
6. 默认餐饮查询有界，只比较部分候选，不代表全城最优；改变路线后可主动重新查询。资料质量不够时，增加接口并不能自动证明推荐适合用户。

7. 最终真实样本仍出现午晚餐之间 246 分钟空档；时间轴如实展示，但本批没有完成全天空档与公共交通选择的优化。因此流程和事实一致性通过不等于整份行程已达到满意质量，应作为后续排程改进的具体样例。
