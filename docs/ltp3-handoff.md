## 正式依据与范围

目标与待办由 Nexo LTP（本机内部记录，链接未公开） 管理。本次执行 LTP-3（本机内部记录，链接未公开），依据已确认决策（本机内部记录，链接未公开），范围为本机单用户、单城市多日旅行。

锁定保护当前日内排序，并不固定预约时间。手动和 AI 重排都须保留锁定位置；移动或删除前先解锁。删除前项后，剩余列表的序号自然缩减。已删除景点仅在用户明确恢复后重新加入，默认追加到列表末尾。重算失败显示上次成功保存状态，并持续提示“本次修改尚未保存”。

接口使用完整状态数组：省略锁定或删除字段则沿用保存状态，传空数组则明确清空。显式解锁可与其他编辑在同一请求中提交；仍处于锁定状态的景点不能移动或删除。未知名称和重复顺序项不会被加入行程。

## 实现与验证

后端 `trip_draft.py` 的 `_merge_day_edit` 统一重算与强制装配，拒绝移动或删除仍锁定的景点，保留省略的字段及餐饮插入位置。AI 输出先校验结构，再恢复锁定位置并排除删除项。路线、预算计算完成后才写入草稿。

前端 `DayCard.vue` 保留锁定、删除、恢复编辑，在操作完成后同步保存状态；`DraftView.vue` 防止同一天重复提交、保存期间定稿，以及失败后显示未保存的本地改动。AI 提示改用页面内对话框，按钮提供景点名称的辅助标签。

## 复验步骤

常规回归在仓库目录执行。后端普通 pytest 默认创建临时 SQLite，避免污染本机行程数据；不要把 `DATABASE_URL` 指向业务数据库运行测试。

```bash
cd backend
.venv/bin/python -m pytest -q --disable-warnings
```

```bash
cd frontend
npm test
npm run build
```

使用模拟服务复验页面，在两个终端分别执行：

```bash
cd backend
PYTHONPATH=. .venv/bin/python tests/manual/ltp3_demo.py
```

```bash
cd frontend
VITE_BACKEND_URL=http://127.0.0.1:18000 npm run dev -- --host 127.0.0.1 --port 5174
```

模拟后端只绑定回环，强制使用新建临时数据库，并输出草稿 URL 和数据目录。打开输出的 URL，锁定狮子林、删除拙政园、执行 AI 重排；狮子林保持当前位置，拙政园不会自动恢复。明确恢复拙政园后可拖拽未锁定景点，跨过锁定位置时锁定位置保持。

在输出的数据目录中创建空文件 `fail-next-route`，下一次重算会模拟 HTTP 503。页面应恢复保存状态，显示尚未保存提示，再次操作成功后清除提示。随后定稿并刷新 `/trip/<历史 ID>`，核对最终顺序与删除结果。此模拟服务不提供发现页搜索，也不调用真实外部服务。

## Nexo 使用问题与处理

操作：在导入项目中创建“本机核心旅程验证”里程碑，使用 `prepare_issue` 将 LTP-3 准备为 READY，再调用 `start_or_continue_work`。

预期：准备后的 Issue 可以开始会话。实际：MCP 返回 `UNAVAILABLE`，提示项目仍处于探索中，需要在项目上下文页提交规划。影响：不能开始会话或记录执行事实。

复现：导入项目保持 EXPLORING → 创建里程碑 → 准备 Issue 为 READY → 使用当前 Issue 版本开始会话。处理：通过项目上下文页正常提交已确认的当前计划，项目进入 PLANNED，重新读取简报并用新请求开始成功。该结果是生命周期前置条件，未认定为 Nexo 缺陷；未修改 Nexo 源码、数据库结构或配置。

此外，当前 Codex 未注册 Nexo 工具，首次环境中也无令牌变量；用户提供本机凭据文件后，通过 Nexo 的 Streamable HTTP MCP 完成读写。凭据未写入仓库或输出。后续接手应使用 `codex-ltp` 正常授权连接，不使用其他来源标签。
