# 数据源评估（LTP-14，2026-10-15）

> 历史快照：本页的版本、测试数、端口、未提交/无Git提交与验收状态对应页内日期，不代表当前状态。当前源码和回归口径见[维护基线](../README.md#verification-baseline)；本机证据未随仓库发布。

结论：保留现有高德和 AIGoHotel 接入，先修正使用方式。酒店必须使用房型详情及明确入住条件，儿童/多房条件不一致时不能用于预算。餐饮优先评估高德 POI 2.0 直连补充菜品标签、电话及照片；本轮只做对照研究，未替换运行链路。现有证据不能证明酒店最便宜、餐厅好吃或推荐更符合用户。

## 实际链路和版本

- 酒店：本机 AIGoHotel 配置 → ModelScope MCP 网关 → `searchHotels` / `getHotelDetail` / `getHotelSearchTags`；详情回传 `rollinggo.cn` 预订页与酒店/报价ID。供应商正式接口部署版本和逐房型上游来源未暴露。道旅官方仓库将 RollingGo 描述为其酒店服务；这是供应方归属线索，不能据此断言当前 ModelScope 实例与官方直连端点完全相同，也不能套用 OAuth v2.3 版本号。
- 美食：高德 MCP `maps_text_search` / `maps_search_detail`；当前 POI 详情保留名称、地址、坐标、人均、评分和营业时间。餐饮候选池并非点评全文或订单库存。对照使用同一 POI ID 的高德 Web Service `/v5/place/detail?show_fields=business,photos`，是同一上游不同传输接口，不能当作第二个独立事实来源。
- Bing 仅可补充检索，不作为可订酒店/餐饮库存或价格来源；既有真实请求被拒绝记录仍有效，本次未宣布恢复。
- 客户端继续使用当前75包依赖锁。没有采用 LTP-9 的111包候选环境，没有购买、注册、签约、下单或迁移供应商。

## 样本与方法

苏州、杭州各6组酒店查询：平日单人1晚、平日双人2晚、周末单人2晚、2成人+8岁儿童2晚、2间各1成人2晚、双人3晚。搜索每组取前2家，再查第一家详情，因此12组条件只涉及2家酒店，不是12家独立酒店。这个便利样本只能检查接口条件和字段，不能代表全国覆盖或推荐质量。日期固定为2026-10-19或23日入住。

两城各取关键词“本地菜 餐厅”前10个不同 POI，共20家；逐一对比 MCP 和 HTTP 详情。调用时间、输入和原始返回在本机证据目录 `~/.local/share/nexo-codex/handoffs/2026-10-15-ltp12-14/sources/` 的 `results.json`；计算结果为 `summary.json`。全部为只读真实请求；非模拟、非订单确认。

12组酒店搜索/详情均返回业务成功且有房型；12个落地链接HTTP均成功，但HTML壳不含可验证价格。用真实浏览器抽查苏州单人及杭州家庭两页，日期可见，房型/早餐/取消政策可见，价格均显示“登录查看价格”。未获取账户，未绕过登录。因此同条件落地成交价一致率为**未验证**，不能写成100%。原始DOM和截图单独留存。

## 酒店主要发现

1. 入住条件回显仅8/12组匹配。两组家庭请求中的儿童数/年龄在预订链接丢失；两组多房请求回显为1间房。详情房型可能变化，但不能据此证明所有条件正确传递。新预算守卫拒绝计入这4组；界面保留未匹配条件。
2. 12/12组详情都有价格、币种、房型、早餐和退改文字；0/12组含明确的税费包含标记。`isOnRequest` 是本次房型响应状态，不是预订成功。普通单房 `averagePrice` 作为整段均价参考，绝不以搜索最低价替代所选房型，不推导折扣。多房单位和完整含税价仍待供应方确认。
3. 搜索的最低展示价与详情最低房型均价只有部分一致，存在小数/取整、房型集合及条件差异。没有可比较的 ratePlanId 时不能据此算“涨价率”或断言错误。整段住宿预算只累加核对过的参考均价；不是可支付订单总价。
4. 城市级搜索首位分别落在昆山与杭州富阳，说明“属于城市”不等于靠近游玩区域。本轮不扩展酒店推荐算法；后续仍需按真实游玩中心与通勤代价筛选。单一供应商排名不能直接变成推荐理由。

## 继续与回退

- 保留：高德地图/POI及AIGoHotel初筛与详情，加入条件核对后使用。暂不把酒店搜索结果直接当作可订房型。
- 补充候选：高德HTTP的菜品标签/电话/照片；后续P05评估界面与推荐理由，沿用明确来源、缓存期限、有限重试和失败保留旧状态。
- 暂不替换：Expedia/Booking/美团/Google均缺本项目实测或准入；不以供应商营销数据作为已验证结论。
- 停止计价条件：身份/日期/宾客回显不符、无房型、单位/币种未知；展示未知并保留上次保存状态，禁止退回星级×200或默认500。
- 回退：本轮未改依赖锁、ORM或运行供应商；代码级回退只使用本次差异补丁，禁止覆盖此前用户未提交成果。旧JSON可读，新增quote字段在JSON内，不迁移业务库；已保存报价只是当次快照，查看详情前仍需重查。
- 待验证：登录后同条件落地价（至少对齐酒店、日期、宾客、房型、餐型、税费与退改）、多房及儿童回显的供应方解释、实际全量覆盖/稳定性、用户对真实候选的采纳。LTP-14不把这些项标为完成。

## 收尾复查补记

最终源码单独复查“景点主查询+城市兜底”时，首次主查询超时、随后城市兜底连接中断，返回空候选；该观察在 `final-live-hotels-first-failed.json` 留存。核查脚本最初没有处理空列表，额外产生IndexError（代理脚本问题，不是供应商返回错误码）；已修正脚本空结果处理。独立重试中单人主查询、双人城市兜底均取得详情并核对日期/人数，见 `final-live-hotels.json`。会话清理仍出现DELETE 404日志，延续LTP-9已知兼容限制，本阶段没有切换依赖或修复该传输行为。失败记录不从质量判断中剔除。
