## 隔离与执行协议

输入从固定 JSON 原样写入新 SQLite；不会复制或连接业务库。每个重复都从头建库，避免沿用上次改动。多城市保留文档/版本/城市快照；普通草稿保留原始 request 与 days_detail。业务源码复制到实验目录，因此日志、运行时数据均在仓库外。源文件清单只含明确的 Python/JSON，不复制 .env、业务 DB、历史日志、个人文件；源码含已有未提交和未跟踪业务实现，均以内容哈希冻结。

worker 环境白名单剔除继承的数据库地址、密钥、代理及 SDK tracing 配置；启动校验数据库必须为本槽新路径，SQLite 审计拒绝其他数据库，参考目录与 .env 读访问被拒绝。默认禁止网络。实际运行仅生成本地 Trace，导出关闭；未修改 P1 开关或凭据。

基线票务显式执行同一 ScheduleCheck 和 rule_key，使用纯规则排序，不伪造模型网络失败。每日基线保留原安排、不写入，以需求未完成作为合理对照。基线没有模型层评分，8 个故障注入场景整槽 N/A。

current_replay 走生产业务代码；模型替身仅按实际过滤候选做规则排序，或保留当前每日顺序/餐次。替身不解读参考答案、不替用户 hint 求解；因此 R01/R02 等需求诊断自然失败，不能用此报告评价真实模型。故障注入直接使用输入 fault，在模型/路线屏障触发：非法 ID、模型超时、取消、双阶段旧 basis、营业冲突、恢复失败、路线期限、并发删除等。R11 使用缩短到 0.03 秒的受控期限触发真实取消，记录原请求期限 110 秒及子任务取消，不冒充等待 110 秒的生产实测。

每个槽位进入 RUNNING 前持久化计划与预留。完成、失败、取消、中断均不自动重跑；恢复只执行尚未调度槽位。不明的前次 RUNNING 变为 INTERRUPTED；真实账单不明时停止继续调度。重复运行不得重新收费或覆盖证据。默认并发 1，支持总墙钟/单槽上限及 CANCEL 文件、SIGINT/SIGTERM。未运行与超时保留分母，不能删掉形成更高成功率。

## 报告边界及发现

所有 30 个案例仍 pending_human；**整份案例的分数均只进入 diagnostic_checks**，formal_checks 为空、formal_quality_score=null、formal_quality_status=NOT_EVALUATED。不只排除主观排名，也不将间接引用参考的披露规则包装成正式成绩。20/10 仍为待来源家族复核的场景分组，未声称独立泛化验证。

报告保留 P/F/E/U/NA、未运行槽位及不同方案适用性。按规则/层/来源/dev-holdout 展示；重复先汇总到单个案例，独立样本数仍 30。操作墙钟与进程启动耗时分开；p50/p95 仅统计成功操作，少于 20 次标小样本，失败/超时/取消的耗时仍在原记录。响应 usage 才计 token，缺失为 null；费用标峰时缓存未命中的估算上界，不声称实际账单。
