# 本机旅行规划查票助手

此目录是本项目的 Chrome/Edge Manifest V3 扩展源码，版本0.2.2。它连接本机规划页面与本次发起的12306/携程查询，不提供购票或支付功能。0.1.1已完成基础Chrome链路；已有安排的旧版适配缺口见[适配性实测](../docs/ltp26-existing-itinerary-handoff.md)。0.2.0新增全天分布采样、自动加载更多航班，应用推荐前由本机服务端按已存日程过滤冲突，同一苏杭完整安排已完成默认高铁/飞机查询→自动排除→真实AI→采用预览保存回读，未手动筛晚班，见[LTP-27交接](../docs/ltp27-handoff.md)。0.2.1修复满80条即提前停止加载及虚拟列表候选ID重复的边界，仍按16轮/稳定3轮上限加载，最后均匀采样最多80条。用户重载0.2.1后，本轮Chrome默认铁路80/航班74条均真实带回，经实际AI、采用预览、保存、刷新完成239项字段核对，见[新版实测](../docs/ltp26-ltp27-followup.md)。满80条后继续航班加载及ID复用边界仍为DOM模拟证据，本次实际航班只有74条；Edge和真人价值仍未验证。

0.2.2 增加铁路查询页同日更换起终点后的会话拒绝；本轮验证为隔离自动化测试，尚未重新安装到真实浏览器验证。

## 安装与使用

1. 启动项目后端与前端，在 Chrome 或 Edge 打开 `http://localhost:5173`。应用和查票必须在同一个浏览器；Codex内置浏览器、Safari和手机暂不支持此扩展。
2. Chrome打开 `chrome://extensions`（Edge为 `edge://extensions`），打开“开发者模式”，点击“加载已解压的扩展程序”，选择此目录。也可从应用下载zip，解压后选择包含manifest.json的目录。
3. 刷新规划页，在大交通区域填写本段条件，点击“打开查票并自动带回”。扩展打开查询页，12306会尝试点击查询；登录、验证码或网站查询失败需用户处理。
4. 铁路从已加载全天列表均匀采样最多80条；航班自动滚动尝试加载更多（最多16轮，稳定后停止并恢复原位置；累计80条后仍继续尝试加载，最后才采样），只读取可识别的直达列表后自动带回，并切回原规划标签页查看最多3条AI推荐。网站滚动加载更多后，可点击网站右下角“重新带回当前列表”，主动重新筛选。
5. 应用先按服务端已保存安排与缓冲过滤冲突（未保存改动须先保存），可展开查看排除原因；AI仅在可容纳候选内排序。卡片说明当前缓冲之外剩余的分钟数，30分钟及以内提示时间较紧；此为已保存安排的算术余量，不是准点保证。点击“采用这班，预览行程”，检查每日窗口、缓冲、预算待确认项，再确认保存。单城保留另一方向交通，多城只变更当前段；不会自动下单或认定已订。

## 权限与数据

- 清单只声明`storage`权限以及本机、12306查询页和携程单程列表的内容脚本。不申请cookies、history、webRequest或所有网站权限。
- 本机脚本运行时限制到`localhost`/`127.0.0.1`的5173、4173和隔离验证15173端口；其他本机服务不参与桥接。原规划页关闭、来源origin变化、查询更改或15分钟超时后关联失效。
- 0.2.0沿用原页面内容脚本确认origin和当前请求，再投递结果；不依赖受权限保护的`tabs.Tab.url`，不新增tabs/host权限。显式航班空结果会传回应用提示，不当作已确认无票或调用模型编造候选。
- 按用户在规划页发起的查询关联新标签页。普通浏览、账户页、订单页不采集；只读取结果行中的班次、站点、时间、席别、参考价和余票标识，不传HTML、网页整段文字、订票令牌、姓名或证件。
- 结构化候选经扩展消息带回原规划页，再发送到本机后端和当前配置的LLM。扩展不保存候选或原始页面；`storage.session`仅保存15分钟内的查询关联，关闭标签或浏览器清理。规划页只在内存保留候选，采用后保存已选择交通字段。
- 读取当前已经加载的部分列表，不代表全站最优或完整覆盖。首版排除中转/经停、候补、无座，铁路优先二等座，其次可用坐席；网站改版可能无法识别，保留原手工路径。
- 页面参考价和余票会变化。航班起价及多人/儿童条件未核准，列表参考价只供筛选并保存在说明，不直接计入预算。来源与接收时间保留，税费/行李/退改及两端接驳继续核对。

## 开发与验证

改扩展后先到扩展管理页点“重新加载”，再刷新规划页和查票页。从zip更新时将新文件解压到原安装目录后重新加载；应用识别到旧版本会显示更新入口。打包命令（不安装到浏览器）：

```bash
python3 scripts/package_ticket_extension.py
```

生成`frontend/public/ticket-assistant-extension.zip`，该生成文件不进入Git。`frontend`下运行`npm run dev`或`npm run build`时会自动先用Python 3打包；生产构建会将下载包带入dist。包内仅含本目录列明的6个文件；变更源码后需重新构建并手动重载扩展。前端测试包含原样读取器DOM样本与MV3消息绑定模拟，后端测试验证候选事实、模型越界/失败/取消和只读API；这些都不能证明真实Chrome权限/网站/跨标签消息已经实装成功。

实现依据：[Chrome内容脚本](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[消息传递](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)、[匹配规则](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns)。安装开发版会获得以上匹配页面的读取能力，用户应检查源码后自行决定安装；卸载即可移除。
